Run Summary

Backend tests use Spring Boot with isolated embedded PostgreSQL 14.10; they did not modify the shared demo database. Browser testing used an authenticated admin session on http://localhost:5174.

Browser workflows used uniquely tagged QA records. Unused QA customers, suppliers, employees, materials, expenses, and user records were deleted. A customer used by the canceled sale was left inactive because it is transaction-referenced. The QA purchase and sales orders remain canceled audit records. Their payments were reversed and inventory, receivables, payables, and dashboard totals returned to pre-test values.

Result: Core implemented workflows passed, with two browser failures: duplicate customer mobile values are accepted, and profile edits are blocked when the existing admin has no mobile number. Automatic token refresh after access-token expiry was inconclusive.

Limitations and Follow-up

  • Backend tests use MockMvc against the full Spring application and isolated PostgreSQL. Browser tests exercised the listed workflows, but not every filter combination, report form, or invalid-input path through the UI.
  • Performance/load testing and comprehensive security assessment were not run. Security coverage here means authentication, token handling, validation, and role authorization tests.
  • Separate vehicle management, delivery tracking, PO approval, sales returns, Remember Me, and opening-stock entry are not available in this build.
  • Customer duplicate prevention is unmet. The uniqueness key, such as mobile or GST, needs a business decision.
  • The Accounts checklist supplied to QA ended after “Accounts Module Validate: Customer…”, so remaining acceptance criteria were blocked.

Backend integration suite: 18 tests, 0 failures, 0 errors. Frontend production build: passed. Test records were isolated or reversed as described above.
