# CSSMS REST API

Base URL: `/api` (Swagger UI: `/swagger-ui.html`, OpenAPI JSON: `/v3/api-docs`).
All endpoints except `/api/auth/login|refresh|forgot-password|reset-password` require `Authorization: Bearer <accessToken>`.
JSON dates are `yyyy-MM-dd`, timestamps ISO-8601, money/quantities are JSON numbers.

## Conventions

**Page response** (all paginated lists):
```json
{ "content": [], "page": 0, "size": 20, "totalElements": 0, "totalPages": 0, "first": true, "last": true }
```
Query params: `page` (0-based), `size` (max 1000), `sort=field,asc|desc`, `search` (free text) plus module filters.

**Error response** (all errors):
```json
{ "timestamp": "...", "status": 400, "error": "Bad Request", "message": "Validation failed", "path": "/api/x", "fieldErrors": { "field": "message" } }
```
`fieldErrors` is only present for validation errors (400). 401 = not authenticated, 403 = role not allowed, 404 = not found, 409 = business rule / duplicate.

**Roles**: `ADMIN`, `MANAGER`, `SALES_EXECUTIVE`.

## Auth

| Method | Path | Body | Response |
|---|---|---|---|
| POST | `/auth/login` | `{username,password}` | `AuthResponse` |
| POST | `/auth/refresh` | `{refreshToken}` | `AuthResponse` |
| POST | `/auth/logout` | `{refreshToken}` | 204 |
| POST | `/auth/change-password` | `{currentPassword,newPassword}` | 204 |
| POST | `/auth/forgot-password` | `{email}` | `{message, resetToken?}` (`resetToken` only when `app.security.expose-reset-token=true`, dev only) |
| POST | `/auth/reset-password` | `{token,newPassword}` | 204 |
| GET | `/auth/me` | - | `UserProfile` |
| PUT | `/auth/me` | `{fullName,email,mobileNumber}` | `UserProfile` |

`AuthResponse`: `{accessToken, refreshToken, tokenType:"Bearer", expiresIn (seconds), user: UserProfile}`
`UserProfile`: `{id, username, fullName, email, mobileNumber, role}`

Password rule: min 8 chars, at least one upper, lower, digit.

## Users (ADMIN)

`GET /users?search&role&page&size&sort`, `GET /users/{id}`, `POST /users`, `PUT /users/{id}`, `DELETE /users/{id}` (soft delete).
Body/response: `{id, username, fullName, email, mobileNumber, role, active, password (request only; optional on update)}`.

## Master data (all: `GET ?search&status&page&size&sort`, `GET /{id}`, `POST`, `PUT /{id}`, `DELETE /{id}` -> 204)

Codes (`employeeCode`, `supplierCode`, `customerCode`, `materialCode`) are generated by the server and ignored on input.
`status` = `ACTIVE | INACTIVE`.

- `/employees`: `{id, employeeCode, fullName, mobileNumber, email, address, joiningDate, salary, designation, status}`
- `/suppliers`: `{id, supplierCode, supplierName, gstNumber?, panNumber?, contactPerson, mobileNumber, address, bankDetails?, status, outstandingAmount (read-only)}`
- `/customers`: `{id, customerCode, customerName, companyName, gstNumber, mobileNumber, email, address, creditLimit, outstandingAmount (read-only), status}`
- `/materials`: `{id, materialCode, materialName, description, unit}` (unit e.g. `TON`; no status filter)

## Purchase orders `/purchase-orders`

- `GET ?search&supplierId&materialId&paymentStatus&status&fromDate&toDate&page&size&sort`
- `GET /{id}`, `POST`, `PUT /{id}`, `POST /{id}/cancel` body `{reason?}`
- Edit/cancel is rejected (409) when a supplier payment exists against the PO.

Request: `{poDate, supplierId, vehicleNumber, remarks, items:[{materialId, quantity, purchaseRatePerTon, gstPercentage}]}`

Response: `{id, poNumber, poDate, supplierId, supplierName, vehicleNumber, materialSummary, totalQuantity, amount, gstAmount, totalAmount, paidAmount, balanceAmount, paymentStatus (PENDING|PARTIAL_PAID|PAID), status (ACTIVE|CANCELLED), remarks, items:[{id, materialId, materialName, quantity, purchaseRatePerTon, gstPercentage, amount, gstAmount, totalAmount}], createdAt}`

Line calc: `amount = quantity*rate`, `gstAmount = amount*gst/100`, `totalAmount = amount+gstAmount`.

## Sales orders `/sales-orders`

- `GET ?search&customerId&materialId&status&paymentStatus&pendingOnly&fromDate&toDate&page&size&sort`
- `GET /{id}`, `POST`, `PUT /{id}`, `POST /{id}/cancel` body `{reason?}`, `GET /{id}/invoice` (PDF `application/pdf`)
- Stock is validated (409 when insufficient) and the customer credit limit is enforced.
- Update/cancel is rejected (409) when customer payments (other than the advance) exist.

Request: `{orderDate, customerId, deliveryAddress, vehicleNumber, advanceAmount, advancePaymentMode?, remarks, items:[{materialId, quantity, rate, discount, gstPercentage}]}`

Response: `{id, salesOrderNumber, invoiceNumber, orderDate, customerId, customerName, deliveryAddress, vehicleNumber, materialSummary, totalQuantity, subTotal, discountTotal, gstAmount, totalAmount, advanceAmount, receivedAmount, pendingAmount, paymentStatus (PENDING|PARTIAL_PAID|PAID), status (ACTIVE|CANCELLED), remarks, items:[{id, materialId, materialName, quantity, rate, discount, gstPercentage, amount, gstAmount, totalAmount}], createdAt}`

Line calc: `amount = quantity*rate - discount`, `gstAmount = amount*gst/100`, `totalAmount = amount+gstAmount`.

## Customer payments `/customer-payments`

`GET ?search&customerId&paymentMode&fromDate&toDate`, `GET /{id}`, `POST`, `DELETE /{id}` (ADMIN/MANAGER; reverses the receipt).
Request: `{paymentDate, customerId, salesOrderId, paymentMode (CASH|UPI|BANK_TRANSFER|CHEQUE), amountReceived, referenceNumber, remarks}`
Response adds `{id, customerName, invoiceNumber}`. `amountReceived` must be <= invoice `pendingAmount`.
Pending invoices for a customer: `GET /sales-orders?customerId=X&pendingOnly=true`.

## Supplier payments `/supplier-payments`

`GET ?search&supplierId&paymentMode&fromDate&toDate`, `GET /{id}`, `POST`, `DELETE /{id}`.
Request: `{paymentDate, supplierId, purchaseOrderId, paymentMode, amountPaid, referenceNumber, remarks}`
Response adds `{id, supplierName, poNumber}`. Pending POs: `GET /purchase-orders?supplierId=X&pendingOnly=true`.

## Expenses `/expenses`

`GET ?search&expenseType&fromDate&toDate`, `GET /{id}`, `POST`, `PUT /{id}`, `DELETE /{id}`
Body/response: `{id, expenseDate, expenseType, amount, description, attachmentName, hasAttachment}`
`expenseType`: `FUEL, VEHICLE_MAINTENANCE, SALARY, OFFICE_EXPENSE, LOADING_CHARGES, ELECTRICITY, RENT, MISCELLANEOUS`
Attachment: `POST /expenses/{id}/attachment` (multipart field `file`, max 5 MB), `GET /expenses/{id}/attachment` (download), `DELETE /expenses/{id}/attachment`.

## Inventory `/inventory`

`GET /inventory?search` -> `[{id, materialId, materialCode, materialName, unit, purchasedStock, soldStock, currentStock}]` (plain array).

## Reports `/reports`

`GET /reports/{key}?...params` -> `ReportResponse`; `GET /reports/{key}/export?format=pdf|xlsx&...params` -> file download.

```json
{ "title": "...", "subtitle": "...",
  "columns": [ { "key": "date", "label": "Date", "type": "TEXT|NUMBER|CURRENCY|DATE" } ],
  "rows": [ { "date": "2026-01-01", "debit": 100.0 } ],
  "summary": [ { "label": "Opening Balance", "value": 0, "type": "CURRENCY|NUMBER|TEXT" } ] }
```

| key | params | Notes |
|---|---|---|
| `stock-current` | - | current stock report |
| `stock-material-wise` | `materialId?` | purchased / sold / current per material |
| `stock-movement` | `fromDate?,toDate?,materialId?` | purchases (IN) and sales (OUT) |
| `purchase-statement` | `fromDate?,toDate?,supplierId?,materialId?,poNumber?` | |
| `sales-statement` | `fromDate?,toDate?,customerId?,materialId?,invoiceNumber?` | |
| `material-profit` | `fromDate?,toDate?` | |
| `customer-statement` | `customerId (required), fromDate?, toDate?` | cols date, particular, debit, credit, balance |
| `supplier-statement` | `supplierId (required), fromDate?, toDate?` | |
| `receivable` | - | per customer with aging days |
| `payable` | - | per supplier with aging days |
| `outstanding-balance` | - | supplier outstanding |
| `customer-payments` | `fromDate?,toDate?,customerId?` | payment report |
| `supplier-payments` | `fromDate?,toDate?,supplierId?` | |
| `expense-report` | `fromDate?,toDate?,expenseType?` | |
| `profit-loss` | `fromDate,toDate` | the UI maps Daily/Monthly/Yearly/Custom to a date range |

## Business-rule notes

* Customer `creditLimit = 0` means no limit is enforced; otherwise a sale is rejected (409) when `outstandingAmount + pending` would exceed it.
* A payment must be made against one invoice (customer) / one PO (supplier) and cannot exceed its pending amount / balance. Deleting a payment reverses it.
* Sales/purchase orders cannot be edited or cancelled while payments (other than the sales advance) exist; cancelling reverses stock, ledgers and balances. Purchases whose stock has already been sold cannot be reversed.
* Master records used by transactions cannot be deleted (409); set `status = INACTIVE` instead. Deletes are soft deletes.
* Sort properties are whitelisted per list endpoint; unknown ones are ignored.
* Swagger UI (`/swagger-ui.html`) is disabled when the `prod` profile is active unless `SWAGGER_ENABLED=true`.
